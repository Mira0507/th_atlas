# th_atlas

This repository contains the code used to quantify and analyze *STMN2* 
cryptic exons (CEs) from single-cell BAM files and to visualize the expression
of marker genes across anterior and posterior thalamic regions of the human brain
using Visium spatial transcriptomics ([Trujillo et al. (placeholder)]()).

## Full methods

### *STMN2* cryptic exon detection

> Splice junctions were extracted and quantified as described by Gittings et al. (Gittings et al. 2023). Input BAM files were generated by mapping sequencing reads to the reference transcriptome using cellranger, followed by ambient RNA removal with cellbender, as described in the manuscript. Mapped reads for the STMN2 gene were filtered from these BAM files and saved as separate BAM files for each barcode annotated to neurons using `samtools view` (v1.19.2; Li et al. 2009). Barcodes that failed to meet the previously described quality control criteria were excluded from the current analysis. Junctions were extracted from each BAM file in parallel using the `regtools junctions extract` command (v1.0.0) with the following parameters: `-s XS -a 6 -m 30 -M 500000` (Cotto et al. 2023). Subsequent junction counting was performed using LeafCutter’s leafcutter_cluster_regtools.py script in Python (v3.9.15) with the following parameters: `-m 10 -p 0.0001` (Li et al. 2018). The resulting junction-by-barcode matrix contained counts for four STMN2 junctions across 46,253 barcodes. By design, LeafCutter excludes rarely used junctions from the matrix. The genomic coordinates of the retained STMN2 junctions were chr8:79611214:79616822, chr8:79611214:79636802,  chr8:79611433:79636802, and  chr8:79611791:79636802, where the naming convention is \<chr\>:\<start\>:\<end\>.
> 
> Detected *STMN2* junctions were annotated using the same GTF annotation file used for read mapping. Each junction was first assigned to a gene based on overlap between the junction coordinates and annotated gene features. To classify junction structure, we extracted the start and end coordinates of all annotated exons and treated them as annotated splice-site boundaries. Junctions for which both the start and end coordinates matched annotated exon boundaries were considered non-cryptic-annotated junctions. Junctions for which one or both coordinates did not match an annotated exon boundary were annotated as cryptic and further evaluated against annotated intronic regions. If one or both junction coordinates were located within an intron, the junction was classified as involving a cryptic exon. Junctions with non-boundary coordinates that did not fall within intronic regions were classified as non-cryptic-novel junctions. No non-cryptic-novel *STMN2* junctions were detected in the current analysis.
> 
> To analyze the ratio of junction counts between cryptic exons and all detected junctions, *STMN2* junction counts were aggregated separately by exon type on a per-sample basis within each neuronal subtype and disease condition. Samples with zero junction counts were excluded prior to normalization, which was performed using a natural log transformation with a pseudocount of 1. For each sample, junction counts for TDP43-affected cryptic exons were divided by the total number of detected junction counts within each neuronal subtype and disease condition. To enable division when the numerator or denominator was zero, a pseudocount was added to all entries before division. The pseudocount was calculated as 1/10 of the minimum non-zero value within each neuronal subtype and disease condition. Sample-wise ratios were used to assess statistical significance between disease and control sample groups using a two-tailed Wilcoxon rank-sum test implemented with the `wilcox.test` function in R. Violin and scatter plots visualizing the distribution of the ratios were generated using the ggplot2 package (v4.0.1) in R. 
> 
> Input BAM files for Sashimi plots were prepared by aggregating per-barcode BAM files into per-subset BAM files, where each subset corresponds to a cell subtype within a disease condition. Technically, per-barcode BAM files and header BAM files were merged using the `samtools cat` command, followed by `samtools sort`. BAM index files were subsequently generated using the `samtools index` command. Sashimi plots were generated by loading these subset-wise BAM files into the Integrative Genome Viewer (IGV v2.16.0; Robinson et al. 2011). Once the Sashimi Plot was opened from the junction track, the minimum displayed junction coverage was set to 4 using the junction coverage display settings. Junction colors were manually set across tracks using the Set Color option. Exported Sashimi plots in SVG format were manually edited using Adobe Illustrator to convert junctions excluded from the quantitative statistical analysis into dashed lines. These Illustrator edits were visual-only and did not affect quantitative junction counting or statistical testing. To generate the reference track, *STMN2* exons were filtered from the GTF annotation file using the rtracklayer package (v1.66.0; Lawrence et al. 2009) in R. The resulting GRanges object was further sliced to include chromosome, start position, end position, gene name, and strand, then exported as a BED file. The reference track for the analyzed junctions was generated by saving genomic coordinates of the junctions as a BED file.

### Spatial transcriptomics

> We obtained the preprocessed 10x Genomics Visium dataset previously generated and published by Schulmann et al. in 2024. Briefly, 14µm-thick fresh frozen coronal sections from the human thalamus were processed via hematoxylin and eosin (H&E) staining, followed by sequencing on an Illumina NextSeq200 system. Sequencing reads were mapped to the human probe set v2.0 using 10x Genomics SpaceRanger v2.1.1. We performed secondary downstream analysis using the pre-filtered Seurat object, from which low-quality spots and genes were removed as described by Schulmann et al. Marker gene expression was visualized using the SpatialFeaturePlot function from the Seurat package (v5.3.0; Hao et al. 2023) in R v4.3.3.

## Input datasets

### *STMN2* cryptic exon detection

The repository does not include large sequencing-derived input files. All reference files
should correspond to the same genome build and gene annotation used during read
alignment; mismatched FASTA, GTF, and BAM references can change junction
coordinates and cryptic-exon annotations.

| Input | Config key or path | Required content | Purpose |
| --- | --- | --- | --- |
| Cell Ranger BAM files | `bam_dir`; one `{SampleID}_possorted_genome_bam.bam` per sample | Genome-aligned BAMs generated by [cellranger count](https://www.10xgenomics.com/support/software/cell-ranger/latest/tutorials/cr-tutorial-ct) | Source reads for barcode- and gene-specific BAM extraction |
| BAM index files | Same directory as BAM files | One `.bai` index per BAM | Required for efficient BAM access |
| Sample metadata CSV | `sampletable` | Must contain the columns configured by `index_col`, `key_col`, `celltype_col`, `study_col`, `disease_col`, and `all_cols`; the workflow uses `bam_col` for constructed BAM paths | Defines sample IDs, grouping variables, disease status, and BAM paths |
| Reference FASTA | `fasta` | Same reference genome FASTA used for `cellranger count` | Used by `regtools junctions extract` |
| Cell-type AnnData files | `adata` | One `.h5ad` file per neuronal subtype; `.obs` must contain barcode and metadata columns listed in `all_cols` | Provides barcode-level cell-type annotations |
| GTF annotation | `workflow/ce/downstream/genes.gtf.gz`, or the path assigned to `gtf_path` in the R Markdown files | Gene annotation matching the reference used for read mapping | Used to annotate junctions, exon boundaries, and cryptic exon status |

The current analysis used three conda environments, as listed below:

## Snakemake for CE extraction

The current analysis uses Snakemake, which runs each step in a pipeline. All 
commands and configurations are designed to be executed within a Snakemake pipeline.

### Configuration

Configure analysis options using the `workflow/ce/config/config.yaml` file, as 
demonstrated below:

#### Sampletable

The following keys are configured in the sampletable:

- Unique sample identifiers. Set the `index_col` option to this column in the following key.
- Paths to input BAM files. Set the `bam_col` option to this column in the following key.
- Optional metadata columns. 
    - Set the `key_col` option to a column you want to aggregate sequencing reads by. 
    This is typically a column for sample groups.
    - Set the `celltype_col` option to a column for cell type annotation.

```yaml

# Path to sampletable
sampletable: "path/to/metadata.csv"
```

#### Reference fasta

This is required to identify the strandness of sequencing reads when extracting
splicing junctions. Specify the reference fasta file you used to run 
``cellranger count``.

```yaml
fasta: "../../input/thalamus_excitatory/genome.fa"
```

#### Columns of interest

Your columns of interest in the sampletable are configured here. Refer to the 
following summary:

- `key_col`: Column for sample groups. Sequencing reads will be aggregated 
by sample group based on this column.
- `index_col`: Unique sample identifiers.
- `bam_col`: Paths to input BAM files. Ensure to use `possorted_genome_bam.bam` 
generated by `cellranger count`.
- `celltype_col`: Column for cell type annotation. Sequencing reads will be aggregated 
by celltype based on this column. Set this option to "" if you don't need celltype-
specific analysis.
- `study_col`: Column for data source.
- `disease_col`: Column for disease condition.

```yaml

# Required column names
key_col: 'study_specific_disease_specific' # column for read aggregation
index_col: 'SampleID'                      # column for unique sample ID, aka index
bam_col: 'bam'                             # column for paths to bam files
celltype_col: 'celltype'                   # column for celltype (leave '' to skip this option)
study_col: 'study'                         # column for data source
disease_col: 'general_disease'             # column for disease condition
```

#### All metadata columns

Oftentimes, the input sampletable contains many columns that are not necessarily informative 
at this point. This key configures column names that will be filtered for the current analysis.
Columns that are unspecified in this key will be removed to keep the analysis concise.


```yaml

# Metadata column for aggregating reads
all_cols: 
  - 'status'
  - 'study'
  - 'Genetics'
  - 'AgeDeath'
  - 'Disease'
  - 'BrainRegion'
  - 'Sex'
  - 'general_disease'
  - 'study_disease'
  - 'study_specific_disease_specific'
```

#### Barcodes

Barcodes are required to filter celltypes of interest. Note that this workflow 
is designed to use the [*AnnData*](https://anndata.readthedocs.io/en/stable/)
object in Python as input material containing barcode information. Set the format to
`celltype: "path/to/anndata"`, as demonstrated below:

```yaml

# Path to AnnData
adata:
  ExNeuRNF220neg: "../../input/thalamus_neurons_reannotated/ExNeuRNF220neg_adata.h5ad"
  ExNeuRNF220pos: "../../input/thalamus_neurons_reannotated/ExNeuRNF220pos_adata.h5ad"
  InNeuSOX14neg: "../../input/thalamus_neurons_reannotated/InNeuSOX14neg_adata.h5ad"
  InNeuSOX14pos: "../../input/thalamus_neurons_reannotated/InNeuSOX14pos_adata.h5ad"
```

#### Paths to input and output directories

Set paths to directories containing input BAM files (`possorted_genome_bam.bam`) and all output files,
using the `bam_dir` and `outdir` keys.

```yaml

# Path to bam directory
bam_dir: '../../input/thalamus_excitatory/bam'

# Path to output directory
outdir: "results"
```

#### Genes of interest

Sequencing reads for genes of interest will be retained in the output BAM file. Specify 
the `genes` key to your genes of interest.

```yaml

# Genes of interest
genes:
  - 'STMN2'
```

#### Analysis name

This will be used as the prefix of the output file name for the junction count
matrix.

```yaml
analysis: 'thalamus_neurons_reannotated'
```

### Snakefile

The Snakefile for this analysis is located at `workflow/ce/Snakefile`. This
workflow filters gene-specific reads from single-cell BAM files, creates
barcode- and group-level BAM files, extracts splice junctions, and generates a
junction count matrix for downstream analysis.

- `create_header`: Checks whether all input BAM files have identical `@SQ`
headers. If the headers are consistent, it writes a shared `header.sam` file for
downstream BAM construction.

- `prep_bam`: Creates sorted and indexed BAM files for each single-cell barcode.
It extracts reads matching the barcode and genes of interest, combines them with
the shared header, and writes per-barcode BAM outputs.

- `aggr_bams_group_celltype`: Aggregates per-barcode BAM files into group- and
celltype-specific BAM files. The merged BAM files are sorted and indexed for
visualization and downstream analyses.

- `extract_junctions`: Extracts splice junctions from each per-barcode BAM file
using `regtools junctions extract`. If extraction fails because a BAM has no
usable reads, the rule creates an empty `.junc` file so the workflow can proceed.

- `prep_juncfiles`: Writes a text file listing all per-barcode junction files.
This file is used as the LeafCutter input list for junction counting.

- `count_junctions`: Runs `leafcutter_cluster_regtools.py` on the prepared
junction file list. The rule generates clustered junction outputs and the final
junction-by-barcode count matrix.

## Downstream statistical analyses for *STMN2* CEs

- `workflow/ce/downstream/sc-exploratory.Rmd`: This R Markdown report imports
the junction-by-barcode matrix and metadata, annotates detected splice junctions
using the GTF file, and adds raw and log-normalized junction counts to AnnData
objects. It performs single-cell QC and exploratory analyses of junction
detection, CE status, gene expression, and per-cell CE metrics, then saves
single-cell and pseudobulk count matrices for downstream analysis.

- `workflow/ce/downstream/sc-pseudobulk.Rmd`: This R Markdown report imports
the pseudobulk matrices generated by `sc-exploratory.Rmd` and compares junction
counts and CE ratios across disease conditions at the sample-celltype level. It
generates QC plots, count and ratio visualizations, pairwise Wilcoxon rank-sum
test results, and BED files for tested junctions and exons.

## Spatial transcriptomics analysis

- `workflow/visium/visium-thalamus.Rmd`: This R Markdown report performs
exploratory analysis of the human thalamus Visium dataset from Schulmann et al.
It imports the preprocessed Seurat object, exports the H&E spatial image, checks
which genes of interest are present in the SCT-normalized expression matrix, and
generates `SpatialFeaturePlot` visualizations for marker genes.
